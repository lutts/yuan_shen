《原神》这款游戏服务端是使用帧同步还是状态同步？
从网络卡顿的表现上来看好像是状态同步

苹果 timer 的精度：

理论上最小精度为 0.1 毫秒。不过由于受 Runloop 的影响，会有 50 ~ 100 毫秒的误差，所以，实际精度可以认为是 0.1 秒。

unity3D引擎相关：
* Time.deltaTime: buff如果是在script里实现的话，有可能使用了deltaTime,  deltaTime: The interval in seconds from the last frame to the current one (Read Only).
   * 如果update是每帧都调用的话，deltaTime就是一帧的时间，但这个时间并不是理想的一帧时间，有误差

   一个游戏循环的定义通常为以下样式：
while (true)
{
  ProcessInput();
  Update();
  Render();
}

在此类游戏循环中，时间增量的计算非常简单：
var time = GetTime();
while (true)
{
    var lastTime = time;
    time = GetTime();
    var deltaTime = time – lastTime;
    ProcessInput();
    Update(deltaTime);
    Render(deltaTime);
}

由此可见，deltaTime会受到 ProcessInput()、Update(), Render()这几个函数执行时间的影响，也就是说，每一帧的处理时间是不同的，导致deltaTime出现波动

每一帧的时间由两部分组成：帧处理与休眠

首先我们需要明确一个认知—UE5的客户端代码和服务器代码是一体的，即两端的代码实际上是混杂在一起的。我们经常听到一种说法叫“前后端分离”，就是服务器干服务器的，客户端干客户端的，二者各为两个工程互不干扰，互相之间通过TCP或者UDP进行通信。而UE5的模式则是客户端和服务器不分离，同在一个工程之中，互相之间的代码使用宏来区分。两种方式各有各的好处。

原神断网后：

* 满命回复效果会停止，可见回复是服务端驱动的，那么我们看到的时间是服务端结算返回客户端的时间点
* 断网3~4秒内，除了不再有伤害数字等蹦出来，角色和怪的动作如常：
	* 砍中怪有命中效果
	* 沙龙成员的动作如常: 有“子弹”打出，有命中效果，但角色不会被扣血
		* 断网了，却有子弹打出，是否是一种预测机制在起作用？
		* 说明三小只扣血的时间点也是服务端结算后返回客户端的时间点
* 断网3~4秒后，界面开始变灰转圈圈，界面不在再接受玩家操作，
	* 但沙龙成员仍然在有规律地行动，只不过不再有“子弹”打出，螃蟹最搞笑，一直在原地保持进攻动作，但就是撞不过去，哈哈哈
		* 这说明沙龙成员的定时行动是由客户端来控制的，但出伤需要服务端结算确认
* 绫华：大招正常转圈，但没有伤害数字蹦出来，可见即便是绫华这样高频出伤的，都是需要和服务器交互

我们可以做一个推论：原神的技能攻击是在客户端计算，但由服务端进行确认结算

在网上查了一下，原神似乎是用的游戏设计中的“状态同步”机制（也有可能是“状态帧同步”）

但对于芙芙满命固定间隔回血这种效果，是如何实现的呢？两种可能的实现逻辑：

1. 服务器每秒推送一个“回血消息”，客户端收到后进行回血操作
2. 客户端每秒发送一个“回血请求”，得到服务器确认后，进行回血操作

客户端请求-服务器回复 这种模式估计很难解决网络问题吧，所以估计是服务器每秒推送
但是：三小只在断网后仍能有规律地行动，那么芙芙每隔一秒的回血也不排除是客户端定时请求的可能

如果是客户端的请求，那么就有一个问题要解决：比如只砍一刀时，客户端在 2.88 秒的时候发出了一个回血请求，但到达服务端的时间是 2.91，是否应该判定为超时？该以何种规则来判定是否超时？
